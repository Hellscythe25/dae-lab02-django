En este laboratorio comprendí cómo viaja la información en Django: la URL llega a una vista, esta arma un `context` y la plantilla lo muestra. Separar así la lógica del HTML hizo que las tres aplicaciones (encuesta, operaciones y cilindro) fueran fáciles de organizar. Durante el desarrollo aparecieron varios problemas que había que resolver. El documento indica el puerto 8080, pero el servidor de Django usa el 8000 por defecto. Además, si el usuario no marcaba la nacionalidad, `request.POST['nacionalidad']` provocaba un error, y lo resolví con `request.POST.get()` y un valor por defecto. También vi que el ejemplo del cilindro escribe los decimales con coma, así que la vista acepta tanto coma como punto y rechaza valores vacíos, cero o negativos mostrando un mensaje. Otra duda fue el resultado del ejemplo del cilindro (6.35338096859), que no coincide con el cálculo exacto (6.35338026803) porque el ejemplo parece usar un π aproximado de 3.141593; usé `math.pi`. Como opinión crítica, el laboratorio es claro para entender el flujo, pero validar los datos a mano se vuelve repetitivo, y sería mejor usar los formularios de Django (`forms.Form`) en un siguiente paso.
